# 03 — Architecture inventory, not a design recommendation

The following is a descriptive inventory. Implemented experiments are not production
promotions. Proposed components are recorded because their contracts exist, not because
they should be adopted. Component ordering below is an index, not a proposed architecture.
For every component, necessity to the original thesis is **not independently established**:
there is no controlled removal study of the whole system. Whether the thesis can survive
without any particular component is an open auditor question, not a removal recommendation.

The executable core modules are packaged under `src/knowledge_compiler/`; their exact hashes
are in the initial manifest. These describe current behavior rather than intended doctrine.

## Scope and necessity limits

Current core executes source normalization → extractor → conservative deduplication →
KnowledgeModel → proposition coverage validation (`pipeline.py`). Representation and
resolution are additional executable consumers, not proof that every experiment forms
one integrated production pipeline. Offline 060–068 machinery must not be mistaken for
an end-to-end live product. Later proposed synthesis/judge contracts remain proposals.

The inventory supplies evidence of local risk containment and some owner-reviewed
presentation benefit. It does not measure each component's independent causal contribution,
necessity, maintenance cost or replacement viability. The recovered prototype demonstrates
its visible outputs without revealing its internal architecture. Neither comparison
licenses a component-preservation or component-removal verdict here.
